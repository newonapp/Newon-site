OVERVIEW

Not a prompt dump —
a work order.

Good results come less from magic phrasing
and more from how you split context.

Turn requirements into a build spec,
lock UI rules,
implement feature by feature,
then fix breakage with the same discipline.

This pack gives that procedure to Cursor
as copyable stages.

HOW TO USE

How to use it.

  1. 01

    Plant project rules first

    Use Setup Prompt to lock stack, folders, and constraints,
    then treat those rules as premises for later prompts.

  2. 02

    Split into a short spec

    Use Requirement Prompt to specify this feature’s
    inputs, outputs, and edge cases briefly.

  3. 03

    Build against UI rules

    Reference UI System, then run Feature Build
    for one feature only.

  4. 04

    Debug in order when it breaks

    Prefer Debugging Workflow over ad-hoc fixes:
    reproduce → cause → fix → re-verify.

  5. 05

    Gate with QA before ship

    Run QA Prompts and the Production Checklist
    for function, responsive, edge cases, and release items.
