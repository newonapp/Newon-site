구성 모듈

프롬프트로 고정합니다.

01

PROJECT SETUP

프로젝트 구조와 기술 스택을
먼저 합의하는 프롬프트입니다.
폴더·규칙·제약을 초기에 심습니다.

02

PRODUCT REQUIREMENT

아이디어를 개발 가능한 명세로 바꿉니다.
모호한 요청을 작업 단위로 쪼갭니다.

03

UI SYSTEM

디자인 시스템과 화면 규칙을 정의합니다.
매 화면마다 스타일이 바뀌지 않게 합니다.

04

FEATURE BUILD

기능 단위로 구현하는 작업 흐름입니다.
한 번에 전체를 만들지 않습니다.

05

REFACTORING

기존 코드를 안전하게 정리하는 방식입니다.
동작 유지를 전제로 구조를 다듬습니다.

06

DEBUGGING

오류 원인 분석 → 수정 → 재검증
순서를 지키는 디버깅 워크플로입니다.

07

QA LIBRARY

기능, UI, 반응형, 예외 상황을
점검하는 프롬프트 모음입니다.

08

PRODUCTION CHECK

배포 전 확인해야 할 최종 항목을
체크리스트로 돌립니다.

결과

Cursor 작업이
반복 가능한 절차가 됩니다.

01

STAGED CONTEXT

한 프롬프트에 모든 것을 넣지 않고
단계별 맥락을 유지할 수 있습니다.

02

FEATURE RHYTHM

기능 단위 구현 → 검증 리듬이
팀이나 개인 루틴으로 자리 잡습니다.

03

SAFER CHANGES

리팩터와 디버깅이
즉흥 수정이 아니라 절차로 남습니다.

04

PRE-SHIP GATE

배포 전 QA·프로덕션 점검이
습관적으로 끼어듭니다.

사용 방법

이렇게 사용합니다.

  1. 01

    프로젝트 규칙을 먼저 심기

    Setup Prompt로 스택·폴더·금지 사항을 정한 뒤
    그 규칙을 이후 프롬프트의 전제로 둡니다.

  2. 02

    명세로 쪼개기

    Requirement Prompt로 이번 기능을
    입력·출력·예외까지 짧게 명세화합니다.

  3. 03

    UI 규칙을 고정한 채 구현

    UI System을 참조하게 한 다음
    Feature Build로 한 기능만 구현합니다.

  4. 04

    깨지면 디버깅 순서로

    즉흥 수정보다 Debugging Workflow로
    재현 → 원인 → 수정 → 재검증을 돌립니다.

  5. 05

    배포 전 QA 라이브러리

    QA Prompt와 Production Checklist로
    기능·반응형·예외·릴리스 항목을 통과시킵니다.
