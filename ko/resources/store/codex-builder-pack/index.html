개요

속도보다 먼저
작업의 경계를 만듭니다.

에이전트는 지시가 넓을수록
관련 없는 파일까지 건드릴 수 있습니다.

저장소 분석, 작업 명세, 멀티파일 변경 규칙,
버그 재현, 코드 리뷰, 검증, 릴리스 준비 —
각 단계에 멈출 지점이 필요합니다.

이 팩은 그 멈출 지점을
프롬프트와 체크리스트로 제공합니다.

구성 모듈

에이전트 루프를
모듈로 나눕니다.

01

REPOSITORY ANALYSIS

기존 프로젝트 구조를 먼저 읽습니다.
진입점, 모듈 경계, 테스트 위치를 파악합니다.

02

TASK SPECIFICATION

에이전트가 소화할 수 있는
명확한 작업 단위로 지시를 씁니다.
성공 조건과 비범위를 함께 적습니다.

03

IMPLEMENTATION WORKFLOW

분석 → 구현 → 검증 순서를 지킵니다.
한 사이클에 한 목표만 넣습니다.

04

MULTI-FILE CHANGE

여러 파일을 건드릴 때의 규칙을 둡니다.
관련 없는 리팩터를 같은 작업에 섞지 않습니다.

05

BUG FIX WORKFLOW

재현 → 원인 분석 → 수정 → 테스트
순서로 버그를 다룹니다.

06

CODE REVIEW

변경의 문제점과 회귀 가능성을
리뷰 프롬프트로 점검합니다.

07

TEST & VALIDATION

자동 테스트와 수동 확인 항목을
같이 돌릴 목록으로 정리합니다.

08

RELEASE PREPARATION

배포 전 최종 검증과
릴리스 노트 골격을 준비합니다.

사용 방법

이렇게 사용합니다.

  1. 01

    저장소부터 읽히기

    Repository Analysis로 구조·진입점·테스트를
    에이전트와 함께 요약한 뒤 수정을 시작합니다.

  2. 02

    작은 작업 명세 쓰기

    Task Spec에 목표, 성공 조건, 건드리면 안 되는 영역을
    짧게 적어 한 사이클에 넣습니다.

  3. 03

    구현 후 바로 검증

    Implementation Workflow로 구현한 다음
    관련 테스트·수동 확인을 같은 사이클에서 끝냅니다.

  4. 04

    멀티파일은 범위 로그

    여러 파일을 바꿀 때는 Change Scope Log에
    의도와 파일 목록을 남기고 Review Prompt를 돌립니다.

  5. 05

    릴리스 준비로 닫기

    Release Preparation으로 최종 검증과
    릴리스 노트 골격을 채운 뒤 배포합니다.
