# ONGIL Responsive + Accessibility Hardening V1

기준 커밋 `cf0b1505e7d748709f4954d6b956e942abfa5b59` (production main), 브랜치 `ongil-responsive-hardening-v1`.

## 1. 무엇을 고쳤나

프로덕션 QA에서 확인된 문제: 320px 화면에서 글씨를 200%로 키우면 기존 ONGIL 화면 일부가 오른쪽으로 잘려 닿을 수 없었다.
새 기능의 회귀가 아니라 예전부터 있던 레이아웃 문제이며, 화면 배치(CSS)만 고쳤다. 마크업·스크립트·데이터·저장 방식·문구는 바꾸지 않았다.

| 대상 | 원인 | 고친 방법 |
| --- | --- | --- |
| 캘린더 월·주·일 선택 | 세 버튼이 한 줄에만 놓이도록 고정되어 카드보다 넓어짐 | 카드가 글씨 크기에 비해 좁을 때만 줄바꿈 허용, 버튼은 자기 글자보다 좁아지지 않음 |
| 캘린더 이전·다음 줄 (월·주·일 보기 공통) | 세 요소가 한 줄에 고정 | 같은 조건에서 날짜를 한 줄에, 이전·다음 버튼을 그 아래에 |
| 캘린더 달력 표 | 위 두 줄이 카드를 넓혀 표도 화면 밖으로 나감 | 카드가 좁을 때 표가 카드 안쪽 여백까지 사용 (하루 칸 44px 이상 유지) |
| 생활비 이전 달·다음 달 | 캘린더와 같은 줄 구조 | 위와 같은 규칙. 합계 줄은 낱말 사이에서 줄바꿈 |
| 건강 날짜 줄 | 옆의 "날짜로 열기" 날짜 입력칸이 자기 최소 너비를 고집해 카드를 넓힘. 날짜 줄 버튼은 글자가 한 자씩 세로로 쪼개짐 | 입력칸은 카드 너비를 넘지 않음. 날짜 줄은 자리가 모자라면 버튼이 아래로 내려감 |

같은 화면(내 생활)에서 함께 재현되어 같은 방식으로 고친 것: 다섯 탭(요약·일정·생활·기록·건강)의 글자 잘림, 목록 항목의 고치기·지우기 버튼, 물 +/− 버튼, 요약 타일의 "보기" 버튼, 화면 상단의 "살펴보기" 버튼.

숨겨서 맞춘 것은 없다: 가로 스크롤 상자, 잘라내기, 글씨 축소, 색·글꼴·크기 변경을 쓰지 않았다.

## 2. 변경 파일

- `ongil-start/styles/ongil-life.css` — 파일 끝에 `[RH1]` 블록 하나 추가 (기존 규칙은 그대로)
- `ongil-start/index.html` — 위 스타일시트 주소의 버전만 변경 (`20261004v13` → `20261007r14`)
- `tests/ongil/responsive-hardening.test.mjs` — RH1-01 … RH1-11
- 기존 테스트 4개 파일의 버전·파일 수 고정값 갱신 (이유 주석 포함)

보통 글씨 크기에서는 그려지는 화면이 같다. 규칙은 (1) 카드가 글씨 크기에 비해 좁을 때만 적용되거나(rem 기준 container query), (2) 넘칠 때만 줄바꿈·축소를 허용한다.
수정 전후 스크린샷 40장(320 / 390 / 768 / 1024 / 1440px × 8개 영역, 100% 글씨)을 픽셀 단위로 비교해 37장이 동일했다.
다른 3장은 320px 캘린더의 날짜 제목 줄바꿈 위치 한 곳이다 ("2026년 10 / 월" → "2026년 / 10월").

## 3. 측정 방법

- Chromium(헤드리스), 로컬 정적 서버, 외부 요청 차단
- 200% 글씨: 문서 루트 글씨 크기를 200%로 설정 (ONGIL의 크기는 rem 기준). 브라우저 확대(zoom) 200%와는 다른 방법이다
- 화면마다: 문서 가로 넘침, 화면 또는 가려진 조상 밖으로 나간 조작 요소, 자기 상자보다 넓은 글자, 부모 밖으로 나간 요소, 44px 미만 조작 요소
- 측정 전 가로 스크롤 위치를 0으로 되돌림 (초점 이동이 화면을 옆으로 밀어 결과를 흐리는 것을 막기 위해)

## 4. 수정 전 (기준 커밋)

| 화면 | 320px + 200% | 390px + 200% |
| --- | --- | --- |
| 캘린더 (월) | 가로 넘침 172px, 잘린 조작 요소 12개 이상 (주·일 버튼, 다음 달, 달력 오른쪽 열) | 넘침 94px, 12개 이상 |
| 캘린더 (주 / 일) | 넘침 136px, 잘린 조작 요소 2개 (일 버튼, 다음 버튼) | 넘침 94px, 2개 |
| 생활비 | 넘침 44px, 다음 달 버튼 잘림, 탭 글자 잘림 | 넘침 0, 합계 줄이 카드 밖으로 57px |
| 건강 (날짜 줄 영역) | 넘침 81px, 날짜 입력칸과 "이 날짜 열기" 잘림 | 넘침 11px, 날짜 입력칸 잘림 |

100% 글씨(320 … 1440px)와 768 / 1440px + 200%에서는 위 세 영역에 넘침이 없었다.

## 5. 수정 후

대상 화면(내 생활: 요약·일정·생활·기록·건강, 캘린더 월·주·일, 생활비, 건강 날짜 줄):

| 화면 폭 | 100% 글씨 | 200% 글씨 |
| --- | --- | --- |
| 320px | 넘침 0 · 잘림 0 · 44px 미만 0 | 넘침 0 · 잘림 0 · 44px 미만 0 |
| 390px | 0 · 0 · 0 | 0 · 0 · 0 |
| 768px | 0 · 0 · 0 | 0 · 0 · 0 |
| 1024px | 0 · 0 · 0 | (측정하지 않음) |
| 1440px | 0 · 0 · 0 | 0 · 0 · 0 |

함께 확인한 화면(변경하지 않음): ONGIL 홈, 건강·안부, 가족, 커뮤니티 — 수정 전후 측정값이 같다.

키보드(320px + 200%): Tab으로 내 생활 화면의 조작 요소 63개를 차례로 지나며 확인 — 화면 밖으로 나간 것 0. 초점 표시는 62개에서 확인했고,
날짜 입력칸 1개는 자동화에서 확인되지 않았다(이번 변경과 무관한 기존 규칙).
동작 확인: 이전·다음 달, 날짜 고르기, 월·주·일 전환, 탭 화살표 이동, 생활비 달 이동과 합계, 날짜 줄 이전 날·오늘과 초점 유지 — 320 / 390 / 1440px에서 모두 그대로.

## 6. 알려진 한계

- 화면 상단의 큰 영문 제목(MY LIFE, HEALTH, FAMILY, COMMUNITY)은 200% 글씨에서 화면보다 넓다. COMMUNITY는 100% 글씨 320 / 390px에서도 넓다. 장식 제목이며 hero 영역이라 이번에 바꾸지 않았다.
- ONGIL 홈 hero의 "시작하기 · 즐길거리" 두 버튼은 320 / 390px + 200%에서 양옆이 일부 잘린다(누를 수는 있다). hero 영역이라 바꾸지 않았다.
- 320px + 200%에서 목록 항목의 고치기·지우기 같은 좁은 버튼은 글자가 세로로 쌓인다. 닿을 수 있고 44px 이상이지만 보기 좋지는 않다.
- 768px + 200%에서 날짜 줄의 "(오늘)"이 자기 줄보다 3px 넓게 측정된다 (수정 전 64px). 잘리지 않는다.
- container query를 지원하지 않는 오래된 브라우저에서는 캘린더·생활비·요약 타일이 수정 전 배치로 보인다.
