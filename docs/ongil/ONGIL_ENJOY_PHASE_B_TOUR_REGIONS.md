# ONGIL Enjoy Phase B — TourAPI regions nationwide

Base: `9453fb60f` (Enjoy V2 Phase A, production). Scope: the tourism source (한국관광공사 TourAPI) only.
Kakao Local and 전국평생학습강좌 adapters are **not touched** — both answer 502 in production today and are handled
separately once the upstream status is known. No festival / event work (type 15, `searchFestival2`) — that is Phase C.

## Why

The route's region table had seven entries and one of them was wrong for today's service:

| Region | Old code | Live result (production route, 2026-10-07) |
| --- | --- | --- |
| 광주 | 29 | **0 items**. The service files 광주 and 전남 together as `전남광주통합특별시`, code **12** (3,677 관광지) |
| 전남 | (46) | 0 items — same merged region, code 12 |
| 강원 | (42) | 0 items; `강원특별자치도` is **51** |
| 전북 | (45) | 0 items; `전북특별자치도` is **52** |
| 세종 | (36) | 0 items; 세종 items carry **36110** as their 시도 code |

So 즐길거리 showed "광주" as supported and answered "nothing found", which was not true.

## What changed

**Server — `server/livon/data/providers/tourapi.mjs`**

- `REGION_CODES`: 서울 11 · 부산 26 · 대구 27 · 인천 28 · **광주·전남 12** · 대전 30 · 울산 31 · **세종 36110** · 경기 41 ·
  강원 51 · 충북 43 · 충남 44 · 전북 52 · 경북 47 · 경남 48 · 제주 50.
- `region=광주` or `region=전남` alone is refused (400). A list named "광주" that quietly contained 전남 would be a
  false label; the only name the route accepts for that data is `광주·전남`.
- `area=` accepts only the codes in the table (세종's five digits included). 29, 36, 42, 45, 46 are refused.
- Nothing else in the adapter changed: same operations, same content types, same normalisation, no caching.

**ONGIL**

- `enjoy-contracts.js`: `ENJOY_REGIONS` (16 choices, natural order), `enjoyRegionFor(profileRegion)`,
  `enjoyRegionParts(id)`.
- `data-source.js`: `TOUR_REGIONS` = those 16 names. A name outside them sends no request.
- `enjoy-view.js`: the 지역 list in "지역에서 찾아보기" is the Enjoy list. The default still comes from 내 정보
  (광주 or 전남 → 광주·전남, with a line that says why). 강좌 and 장소 are per-시·도 sources, so for 광주·전남 they are
  asked once per region and put together; if one part cannot be read the result says so, and if none can it is
  "unavailable", never "nothing found".
- `index.html`: import-map versions of the three changed modules (generated by `scripts/ongil-module-versions.mjs`).
  The entry `app.js?v=20261007e16` did not change.

**Not changed**: 내 정보 regions (17 시·도; a stored 광주 or 전남 stays valid), Saved, calendar, tasks, community, family,
the six categories, search targets, filters, sort, pagination, detail, stylesheets, content types (ONGIL asks for
12 관광지 · 14 문화시설 · 28 레포츠 only).

## Not verified here

- `lDongRegnCd=36110` as a **list filter** against the live service. The evidence is that live 세종 items carry
  36110 as their 시도 code and that 36 returns nothing; the route could not be asked with 36110 before this change.
  Check `?provider=kr-tourapi&region=세종&type=12` on a preview deployment before production.
- Real browser zoom, real screen reader, real devices.

## Known limitations

- LIVON Explore still offers "광주" for 관광정보 (LIVON product code is out of scope here). Before: an empty list
  (code 29). Now: the route refuses the name (400) instead of answering with an empty list; how the LIVON screen words that was not
  checked here. LIVON needs its own follow-up (offer 광주·전남, or drop 광주).
- Items from 광주·전남 carry no short region label on the result row (the address line shows 전남광주통합특별시 …).
- 강좌 / 장소 for 광주·전남 make two requests (one per 시·도).
