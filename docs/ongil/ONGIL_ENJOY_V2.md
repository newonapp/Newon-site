# ONGIL Enjoy + Local Discovery V2 — Phase A

기준: main `cc08c9068f60b052473344e7e0185daedcdf3175`, 브랜치 `ongil-enjoy-v2`.
기존 즐길거리(Enjoy + Local Discovery V1, Phase 5)를 버리지 않고 같은 `#enjoy` 화면을 넓혔다. 새 저장소·새 API·서버 변경은 없다.

## 1. 화면 순서

| 순서 | 카드 | 내용 | 상태 |
| --- | --- | --- | --- |
| A | 오늘 뭐 하지? | 내 정보에서 직접 고른 관심사 → 같은 이름의 분류로 가는 바로가기 | 새로 추가 |
| B | 내 관심사 · 내 지역 | 내 정보에 적어 둔 것과 고치러 가는 길 | 새로 추가 |
| C | 무엇을 해볼까요? · 지역에서 찾아보기 | 분류 6개, 지역 + 대상 검색, 자료 연결 상태 | V1 유지 + 상태 줄 |
| D | 찾은 즐길거리 | 필터·검색·정렬·30개씩·자세히 | V1 유지 |
| E | 저장한 즐길거리 (저장한 활동) | 개수 + 실제 목록, 자세히, 저장 취소 | 목록 추가 |
| F | 내가 쓴 관련 글 | 즐길거리에서 ‘후기 쓰기’로 시작한 내 글 | 새로 추가 |

## 2. 오늘 뭐 하지? — 추천이 아니다

- 기존 관심사 8개를 그대로 쓴다. 새 관심사 항목이나 저장 칸은 없다.
- 운동 → 운동, 취미 → 취미, 배움 → 배움, 문화 → 문화, 나들이·여행 → 나들이 · 여행.
- 건강, 모임·이웃, 가족은 해당 분류가 없어 바로가기를 만들지 않는다 (짐작해서 연결하지 않는다).
- 바로가기는 분류만 고른다. 검색은 사용자가 ‘찾기’를 눌러야 시작된다.
- 건강·가족·나이·내 생활 기록은 읽지 않는다. 점수·순위·인기·"맞춤" 표현이 없다.

## 3. 내 관심사 · 내 지역

- 내 정보의 관심사와 지역(시·도 17개 중 직접 고른 것)만 읽는다. 고치기는 내 정보(`#account`)로 연결.
- 위치 권한을 묻지 않고, GPS·백그라운드 위치를 쓰지 않는다.

## 4. 자료 연결 상태

자료 세 가지를 따로 보여 준다: 관광 정보(한국관광공사), 평생학습 강좌, 장소(지도 검색).
이번 방문에서 실제로 받은 응답으로만 정한다 — "아직 찾아보지 않았어요 / 자료를 받아왔어요 / 찾은 것이 없었어요 / 받아오지 못했어요".
코드에 "고장"이라고 적어 둔 자료는 없다. 자료가 복구되면 그대로 "받아왔어요"로 바뀐다.

2026-10-07 production 상태 (참고, 코드에는 반영하지 않음):

| 자료 | 상태 |
| --- | --- |
| TourAPI (관광지·문화시설·레포츠, 7개 시·도) | 응답함 |
| Kakao 장소 | 502 UPSTREAM_ERROR |
| 평생학습 강좌 | 502 UPSTREAM_ERROR |

그래서 지금 production에서는 문화·나들이·운동·여행만 결과가 나오고 취미·배움은 "받아오지 못했어요"로 보인다. 가짜 결과로 채우지 않는다.
502 원인 조사와 TourAPI 행사 유형 확대는 Phase B (서버 작업)이다.

## 5. 저장한 활동

- 기존 Saved 저장소의 PROGRAM · PLACE 항목을 그대로 읽어 목록으로 보여 준다. 복사본이나 새 저장소는 없다.
- 이번 방문에서 찾은 항목이면 전체 정보로, 아니면 저장할 때 적어 둔 내용(이름·설명·출처·링크)만으로 ‘자세히’를 연다.
- 목록의 ‘저장 취소’와 자세히의 저장 버튼은 같은 Saved 항목을 가리킨다.

## 6. 내 생활 연결

| 기능 | 대상 | 방식 |
| --- | --- | --- |
| 내 일정에 추가 | 실제 시작일이 있는 강좌 | V1 그대로 |
| 날짜 골라 일정에 추가 | 장소 등 날짜가 없는 것 | 날짜(오늘 이후)와 시간(선택)을 직접 고름 → 미리보기 → 추가 |
| 할 일로 추가 | 모든 항목 | "○○ 가 보기 / 알아보기" 제목만, 기한 없음 → 미리보기 → 추가 |

- 기존 일정 저장소와 할 일 저장소에만 쓴다. 같은 제목·날짜·시간의 일정, 같은 제목의 끝내지 않은 할 일은 다시 추가하지 않는다.
- 자료 출처나 주소는 일정·할 일에 복사하지 않는다. 신청·예약이 되는 것이 아님을 미리보기마다 밝힌다.

## 7. 커뮤니티 · 가족

- 내가 쓴 관련 글: 이 기기에서 내가 쓴 글 중 즐길거리 항목에서 시작한 것만. 제목과 글로 가는 링크만 읽는다. 다른 사람 글·참여 인원·인기 모임은 없다.
- 후기 쓰기: V1 그대로 (커뮤니티 글쓰기에 제목만 채워 넘김, 저장 전에는 아무것도 쓰지 않음).
- 가족에게 보여주기: V1 그대로 미리보기만. 보내는 기능은 없다.

## 8. 개인정보

- 둘러본 기록을 저장하지 않는다. 찾은 결과는 방문 중 메모리에만 있다.
- 주소에는 분류 이름만 들어간다. 즐길거리 화면이 직접 네트워크를 부르지 않는다 (기존 data-source 경유, 지역 이름과 찾을 말만 전송).
- 전체 검색에는 이번 방문에서 찾은 공개 항목만 나온다.

## 9. 변경 파일

- `ongil-start/js/enjoy-view.js`, `enjoy-contracts.js` — 화면과 순수 함수
- `ongil-start/js/app.js` — 할 일 저장소와 내 글 목록을 넘겨주고, 화면에 들어올 때 다시 읽기
- `ongil-start/index.html` — 모듈 버전 (공식 스크립트로 생성)과 진입 스크립트 버전
- `tests/ongil/enjoy-v2.test.mjs` (EV2-01 … 23), 기존 테스트의 고정값 갱신, 이 문서
- 스타일시트 변경 없음. 서버·API·DB·env 변경 없음. LIVON 파일 변경 없음.

  - 화면 폭 320 / 390 / 768 / 1024 / 1440px × 글씨 100% / 200% (루트 글씨 크기)

## 11. 알려진 한계

- production에서 Kakao·평생학습 자료가 응답하지 않아 취미·배움은 결과가 없다 (Phase B).
- 관광 정보는 서울·부산·대구·인천·광주·대전·경기만 지원한다 (서버 adapter의 지역 코드, Phase B).
- 공연·행사 일정, 지역 프로그램, 공개 모임 자료는 없다.
- 저장 항목을 새로고침 뒤에 열면 저장할 때 적어 둔 내용만 보인다 (자료 원문을 저장하지 않기 때문).
- 건강·모임·이웃·가족 관심사는 바로가기가 없다.
- 320px + 200%에서 좁은 버튼의 글자가 세로로 쌓이는 기존 현상은 그대로다.
