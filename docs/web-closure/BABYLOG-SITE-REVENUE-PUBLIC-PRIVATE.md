# BABYLOG 웹사이트 — 수익 정책 공개/비공개 구분

기준: 작업 지시서 §7 "내부 수익 정책 참고(사업 기획 가설)". 이 문서와 저장소에는 **내부 가설의 숫자(요금, 수수료율, 구독료, 계약 금액대)를 적지 않는다.** 숫자는 지시서 원문에만 있다.

## 1. 구분 원칙

| 구분 | 공개 웹사이트에 표시 | 표시하지 않음 |
|---|---|---|
| 확정 요금·수수료 | 실제 출시·승인된 것만 (현재 0건) | — |
| 검토 중인 수익 구조 | **유형**만 문장으로 ("구독형", "거래 연계", "계약형", "라이선스 계약") + "확정된 요금은 없습니다" | 금액, 비율, 범위, 기간 |
| 내부 가설 | 없음 | 개인·가족 요금, 판매자 수수료율, 기업 기본 수수료, 대량 판매자 차등, 기관 SaaS 금액대 |
| 이중 수수료 | "하나의 거래에 수수료가 이중으로 부과되지 않도록 구조를 설계하는 것이 원칙이며 확정된 정책은 아님" | 구체적 분배 방식 |

## 2. 페이지별 공개 수준

| 페이지 | 수익 관련 표시 | 비고 |
|---|---|---|
| Overview | "모든 사업 영역은 출시 전 검토 단계, 확정된 요금과 수수료는 공개하지 않음" | 숫자 없음 |
| Platform | SHAREON 연계는 방향으로만 표시, "웹에 거래 기능 없음" | 라벨: 검토 중 |
| Business | 영역 A~F 각각 "수익 모델" 칸에 구조 유형만. 상단에 "가격이 아닌 검토 중인 구조 유형" 안내 | 라벨: 검토 중 / 방향 |
| Partnerships | 8개 유형별 "수익 구조" 칸에 구조 유형만. "확정된 조건은 없습니다" | 판매자·브랜드 유형은 이중 수수료 방지 원칙만 |
| Contact | 구독·결제 문의는 "아직 출시되지 않은 상품은 안내만 가능" | 결제 기능 없음 |

## 3. 자동 방지

- `scripts/qa-babylog-site.mjs`의 `revenue` 검사가 5개 페이지 × 9개 언어 본문에서 금액·비율 패턴(₩, 원, %, 천 단위 숫자, "월 N만", 알려진 내부 수치)을 찾으면 FAIL.
- `tests/web/babylog-site.test.mjs` BL-2(페이지에 금액 삽입 시 FAIL), BL-6(카피 모듈에 금액·비율 없음).
- 이 검사는 `fast-check`에 포함되어 CI(build-guards)에서도 실행된다.

## 4. 공개 전환 절차 (요금이 확정되었을 때)

1. 소유자가 항목별 요금·수수료를 승인한다(출시·승인 기록 필요).
2. 승인된 항목만 `babylog-site-copy.mjs`에 문장으로 추가하고 `qa-babylog-site.mjs`의 `revenue` 예외에 근거를 명시한다.
3. 번역은 `i18n-approved/`를 통해서만 7개 언어에 반영한다.

## 5. 웹에 만들지 않은 것

결제, 수수료 계산, 판매자 등록·계정 생성, 계약 전자서명, 주문·예약. 파트너 유형 UI는 소개 내용을 보여 주는 앵커 링크 목록이며 입력·저장 기능이 없다.
