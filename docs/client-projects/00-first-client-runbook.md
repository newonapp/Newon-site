# 첫 외주 고객 운영 런북 (내부)

**대상:** Newon 운영자  
**목적:** Studio/Business 문의가 들어온 날, **무엇부터 어떤 순서로** 할지 바로 실행한다.  
**성격:** 내부 운영 가이드. 고객에게 그대로 보내지 않는다. 법률·세무 자문을 대체하지 않는다.

관련 템플릿: [01](./01-requirements-questionnaire.md)~[08](./08-acceptance-form.md), [10](./10-client-project-agreement-template.md), [11](./11-mid-project-update.md).  
기본 정책 결정 기록: [09](./09-policy-decision-sheet.md). 목록: [README](./README.md).

## 0. 오늘 문의가 들어왔을 때 (15분 체크)

### 0-A. 문의 Source of Truth (현재)

공개 웹 문의의 **공식 수신처는 `newon@newon.app` 메일함**이다.  
FormSubmit → HQ `hq_leads` **자동 적재를 가정하지 않는다.** (Archive sync / webhook은 별도 작업·미연결일 수 있음.)

운영 흐름:

```
웹 문의 폼 제출
  → newon@newon.app 수신 확인
  → 고객 기본정보·요구 요약 확인
  → 필요 시 HQ 문의/Clients에 수동 등록
  → 회신 · 01 질문지 (또는 상담)
```

메일 확인 시 **받은편지함 + 스팸 + 프로모션/업데이트 등 자동 분류함**을 본다.  
고객 메일 본문·개인정보·credential을 Git/저장소 문서에 **복사·커밋하지 않는다.**

### 0-B. 당일 체크리스트

1. **문의 확인** — `newon@newon.app` (위 §0-A). HQ에 이미 있으면 상태만 맞춤. **없으면 메일 기준**으로 처리 후 필요 시 HQ 수동 등록  
2. **스팸·중복 제외** 후 상태: 신규 → 확인 중  
3. **서비스 축 판별**  
   - Studio만 (브랜드·디자인·콘텐츠·IP · Digital Design Only 가능)  
   - Business BUILD / AUTOMATION / RESEARCH / SOLUTIONS  
   - Studio + BUILD 연계  
4. **회신 초안** — 감사 + 다음 단계(상담 또는 질문지) + 대략 일정감만. **확정 금액은 견적 전까지 약속하지 않음**  
5. HQ에 **Clients**(해당 시) 초안 메모 / 문의 노트 남기기 (메일에서 이관한 경우)

## 1. 고객이 보는 흐름 (공개)

```
Studio(또는 Business) 서비스 이해
  → CTA 「프로젝트 문의」
  → /business/inquiry/?category=Studio (또는 해당 서비스 프리필)
  → 폼 제출 (회사·이름·이메일·유형·예산·단계·희망 일정·설명)
  → 이메일 접수 → Newon 회신
```

문의 폼이 이미 받는 최소 정보:

| 항목 | 폼 필드 | 비고 |
|------|---------|------|
| 서비스 종류 | `type` (+ URL `service`/`category`) | Studio 옵션 포함 |
| 목적·결과물 감 | `message` | 상세는 01 질문지에서 |
| 희망 일정 | `timeline` (선택) | |
| 예산 범위 | `budget` | 참고용 안내 문구 있음 |
| 참고 URL | `website` (선택) | 레퍼런스는 상담·01에서 보강 |
| 단계 | `stage` | 아이디어~운영 등 |

폼을 더 길게 만들지 않는다. 부족한 항목은 **상담 + 01 질문지**로 받는다.

## 2. Newon 내부 운영 흐름 (문의 → 납품)

```
문의 접수 (공개 폼 → newon@newon.app · §0-A)
  → (선택) HQ 문의 수동 등록
  → 상담 · 요구사항 확인 …… 01 질문지
  → 견적 …………………………… 02
  → 범위 확정 ……………………… 03 SoW
  → 계약 전 점검 ………………… 04 (내부)
  → 합의/계약 초안 …………… 10 (해당 시 · 법률 검토 전 초안)
  → 계약·계약금 확인 · HQ Project 생성
  → 고객 진행 안내 …………… 05
  → Tasks / 중간 공유 ………… 11
  → 변경 요청 시 ………………… 06
  → 내부 QA ………………………… 07
  → 고객 검수 · 수정
  → 납품 · 인수 확인 …………… 08
  → 잔금 확인 · 최종 산출물 인계
  → 30일 Newon 구현 오류 대응 (이후 유지보수는 별도 합의)
```

### HQ와의 매핑 (현재 구조)

| 단계 | HQ | 문서 |
|------|-----|------|
| 리드 접수·상태 | **문의** | — |
| 고객 마스터 | **Clients** (전환·생성) | — |
| 계약 후 납품 단위 | **Projects** | 03·05 |
| 할 일·기한 | **Tasks** | 05·06 |
| 수입·지출 기록 | **Finance** (합의·입금 후) | 02 · 10 |
| 앱/스토어 출시 | **Releases** (해당 시) | 07 |

스키마를 새로 만들지 않는다. 없는 필드(미수·SLA 등)는 문서·메모로만 운영한다.

## 5. 고객 무응답 — 내부 처리

고객 안내는 [05](./05-project-guide.md)와 동일 기준. 자동 승인·자동 종료로 처리하지 않는다.

| 경과 | 내부 액션 |
|------|-----------|
| **5영업일** | 진행 확인·필요 자료/피드백 재안내. HQ Task/메모에 기록 |
| **10영업일** | 일시 보류 가능. 기존 납품일 유지 보장 안 함. 고객에 보류 사실·재개 조건 안내 |
| **30일 이상** | 계약·진행률·완료 작업·발생 비용을 확인해 **종료 및 정산 절차 검토**. 일방적 자동 종료 금지 |

보류 후 고객 복귀 시: **현재 Newon 일정** 기준으로 재개일·납품일을 다시 협의한다.

## 6. 하지 말 것

- 저장소 템플릿에 계좌·주민·실명 민감정보 커밋  
- Secret/비밀번호를 코드·일반 문서·공개 저장소에 평문 저장  
- FormSubmit/Archive Sync를 “문의가 안 온다”고 임의 배포·재개 (별도 작업)  
- HQ에 문의가 **자동으로** 들어온다고 가정하고 메일함을 확인하지 않기  
- HQ에 mock 문의·가짜 매출 생성  
- Studio Design Only 범위에 BUILD를 조용히 포함  
- 승인 전 범위 밖 CR 작업 착수  
- 무응답을 자동 승인/자동 종료로 처리  
- 「계약금 무조건 환불 불가」 같은 절대 문구로 고객 안내
