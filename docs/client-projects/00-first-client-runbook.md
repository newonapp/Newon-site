# 첫 외주 고객 운영 런북 (내부)

**대상:** Newon 운영자  
**목적:** Studio/Business 문의가 들어온 날, **무엇부터 어떤 순서로** 할지 바로 실행한다.  
**성격:** 내부 운영 가이드. 고객에게 그대로 보내지 않는다. 법률·세무 자문을 대체하지 않는다.

관련 고객용·합의용 템플릿은 [01](./01-requirements-questionnaire.md)~[08](./08-acceptance-form.md), 목록은 [README](./README.md).

---

## 0. 오늘 문의가 들어왔을 때 (15분 체크)

1. **문의 확인** — 공개 문의 폼 → 이메일 / (연결 후) HQ **문의**에서 접수 확인  
2. **스팸·중복 제외** 후 상태: 신규 → 확인 중  
3. **서비스 축 판별**  
   - Studio만 (브랜드·디자인·콘텐츠·IP · Digital Design Only 가능)  
   - Business BUILD / AUTOMATION / RESEARCH / SOLUTIONS  
   - Studio + BUILD 연계  
4. **회신 초안** — 감사 + 다음 단계(상담 또는 질문지) + 대략 일정감만. **확정 금액·미결정 정책 수치를 약속하지 않음**  
5. HQ에 **Clients**(해당 시) 초안 메모 / 문의 노트 남기기  

---

## 1. 고객이 보는 흐름 (공개)

```
Studio(또는 Business) 서비스 이해
  → CTA 「프로젝트 문의」
  → /business/inquiry/?category=Studio (또는 해당 서비스 프리필)
  → 폼 제출 (회사·이름·이메일·유형·예산·단계·희망 일정·설명)
  → 이메일 접수 → Newon 회신
```

문의 폼이 이미 받는 최소 정보:

| 항목 | 폼 필드 | 비고 |
|------|---------|------|
| 서비스 종류 | `type` (+ URL `service`/`category`) | Studio 옵션 포함 |
| 목적·결과물 감 | `message` | 상세는 01 질문지에서 |
| 희망 일정 | `timeline` (선택) | |
| 예산 범위 | `budget` | 참고용 안내 문구 있음 |
| 참고 URL | `website` (선택) | 레퍼런스는 상담·01에서 보강 |
| 단계 | `stage` | 아이디어~운영 등 |

폼을 더 길게 만들지 않는다. 부족한 항목은 **상담 + 01 질문지**로 받는다.

## 2. Newon 내부 운영 흐름 (문의 → 납품)

```
문의 접수 (공개 폼 / 메일)
  → HQ 문의 상태 관리
  → 상담 · 요구사항 확인 …… 01 질문지
  → 견적 …………………………… 02
  → 범위 확정 ……………………… 03 SoW
  → 계약 전 점검 ………………… 04 (내부)
  → 계약·착수 · HQ Project 생성
  → 고객 진행 안내 …………… 05
  → Tasks / 중간 공유
  → 변경 요청 시 ………………… 06
  → 내부 QA ………………………… 07
  → 고객 검수 · 수정
  → 납품 · 인수 확인 …………… 08
  → 완료 · (유지보수는 별도 합의 시에만)
```

### HQ와의 매핑 (현재 구조)

| 단계 | HQ | 문서 |
|------|-----|------|
| 리드 접수·상태 | **문의** | — |
| 고객 마스터 | **Clients** (전환·생성) | — |
| 계약 후 납품 단위 | **Projects** | 03·05 |
| 할 일·기한 | **Tasks** | 05·06 |
| 수입·지출 기록 | **Finance** (합의·입금 후) | 02 결제란은 합의 후 기입 |
| 앱/스토어 출시 | **Releases** (해당 시) | 07 |

스키마를 새로 만들지 않는다. 없는 필드(미수·SLA 등)는 문서·메모로만 운영한다.

## 4. 아직 확정하지 않은 사업 정책 (임의 기입 금지)

아래는 **운영자가 프로젝트마다 또는 사업 차원에서 결정**해야 한다.  
이 런북·템플릿에 숫자를 박아 넣지 말고, 결정 후 SoW/견적/계약에만 기입한다.

| 주제 | 결정이 필요한 내용 | 반영 위치 (결정 후) |
|------|-------------------|---------------------|
| 결제 비율·시점 | 착수/중도/잔금 비율·트리거 | 02 · 계약 |
| 기본 수정 횟수·라운드 | 디자인/개발 피드백 한도 | 03 · 06 합의란 |
| 고객 검수 기간 | 일수·시작 기준 | 03 · 05 · 08 |
| 견적 유효기간 | 기본일수 | 02 |
| 유지보수 | 납품 후 포함 여부·기간·별도 계약 | 03 · 08 |
| 계약·세금계산서 | 계약 형식, 세금계산서 발행 주체·시점 | 02 · 계약 |
| 개인정보·고객 데이터 | 처리 역할, 보관·파기, 약관 작성 주체 | 04 · 계약 |
| 계정·Secret 인계 | 고객 계정 원칙, 공유 방식, 회수 | 04 · 07 |
| Design Only → BUILD | 전환 견적·일정·권리·파일 인수 | 03 · 별도 견적 |
| (전체 선택지) | → [09-policy-decision-sheet.md](./09-policy-decision-sheet.md) | |

## 5. 하지 말 것

- 미결정 정책 수치를 고객에게 확정처럼 약속  
- 저장소 템플릿에 계좌·주민·실명 민감정보 커밋  
- FormSubmit/Archive Sync를 “문의가 안 온다”고 임의 배포·재개 (별도 작업)  
- HQ에 mock 문의·가짜 매출 생성  
- Studio Design Only 범위에 BUILD를 조용히 포함
