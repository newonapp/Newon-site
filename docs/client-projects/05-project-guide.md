# 프로젝트 진행 안내서

> 고객과 Newon이 **같은 순서·역할**을 공유하기 위한 안내입니다.  
> 프로젝트 유형(Studio만 / BUILD / 혼합)에 따라 일부 단계는 생략되거나 길이가 달라질 수 있습니다.  
> **결제 비율, 수정 횟수, 검수 기간 등 수치는 이 안내서에 고정하지 않습니다.** 해당 프로젝트 견적·SoW·계약에서 확정한 값만 따릅니다.

---

## 한눈에 보기

```
상담
 → 요구사항 확정
 → 견적
 → 계약 · 착수
 → 기획
 → 디자인
 → 개발 (해당 시)
 → 내부 QA
 → 고객 검수
 → 수정
 → 최종 납품
```

내부 당일 실행 순서·HQ(문의/Clients/Projects/Tasks) 연결은  
[00-first-client-runbook.md](./00-first-client-runbook.md)를 참고합니다. (고객 공유용 아님)

---

## 1. 상담

**목적:** 목표·대략 범위·서비스 축(Studio / Business)을 파악합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 상담 요약, 필요 시 질문지·다음 단계 안내 |
| 고객이 준비할 것 | 목적, 레퍼런스, 희망 일정·예산 감, 의사결정자 |
| Newon | 질문·범위 가설, Studio Design Only vs BUILD 구분 안내 |

---

## 2. 요구사항 확정

**목적:** 이후 견적·SoW의 기준을 만듭니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 정리된 요구사항(질문지 또는 동등 문서) |
| 고객이 준비할 것 | 질문지 회신·수정, 우선순위(Must/Should) 확정 |
| Newon | [01-requirements-questionnaire.md](./01-requirements-questionnaire.md) 기준 정리 |

---

## 3. 견적

**목적:** 범위에 대한 제안 금액·일정 골격을 제시합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 견적서 (유효기간 명시) |
| 고객이 준비할 것 | 검토·질의, 옵션 선택 여부 |
| Newon | [02-quote-template.md](./02-quote-template.md) 작성 · 사이트 시작가·별도 견적 체계 준수 |

---

## 4. 계약 · 착수

**목적:** 범위·대가·일정을 합의하고 작업을 시작합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | SoW, 계약(또는 서면 합의), 킥오프 일정, 진행 안내 |
| 고객이 준비할 것 | 승인, 착수 조건(결제 등) 이행, 자료·계정 제공 시작 |
| Newon | [03](./03-scope-of-work.md)·[04](./04-pre-contract-checklist.md) 통과 후 킥오프 |

착수 기준(예시): 합의 문서 서명(또는 동등 확인) + 착수 조건 충족 + Critical 자료 수령.

---

## 5. 기획

**목적:** 정보 구조·플로우·화면·콘텐츠 구조를 합의합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | IA/플로우, 화면 목록, 기획 메모 또는 와이어 수준 산출물(합의 형식) |
| 고객이 준비할 것 | 피드백, 콘텐츠 초안·우선순위, 비즈니스 규칙 확인 |
| Newon | 범위 내 기획 · 범위 밖 요청은 변경 정책으로 분리 |

Studio 브랜드·콘텐츠만인 경우: 전략·콘셉트·콘텐츠 구조 중심으로 진행할 수 있습니다.

---

## 6. 디자인

**목적:** 합의된 시각·UI를 확정합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 디자인 시안·프로토타입(합의 툴), 수정본 |
| 고객이 준비할 것 | 브랜드 자산, 피드백(한곳에 모아 전달 권장) |
| Newon | SoW 디자인 범위 내 제작 · 합의된 수정 한도 적용 |

**Design Only(Studio Digital)** 로 끝나는 경우: 이후 개발 단계는 없거나, Business BUILD는 **별도 계약**으로 이어갑니다.

---

## 7. 개발 (해당 시)

**목적:** 합의된 기능·플랫폼을 구현합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 진행 공유, 스테이징/빌드 접근(합의 시) |
| 고객이 준비할 것 | API·계정·도메인, 약관 문구, 테스트 계정 정보 |
| Newon | SoW 개발 범위 구현 · 환경변수·Secret은 안전하게 관리 |

---

## 8. 내부 QA

**목적:** 고객 검수 전에 Critical 이슈를 줄입니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 검수 가능 안내, 체크 포인트 요약(선택) |
| 고객이 준비할 것 | 검수 일정 확보 |
| Newon | [07-delivery-checklist.md](./07-delivery-checklist.md) 기반으로 내부 점검 |

---

## 9. 고객 검수

**목적:** SoW 기준 합격 여부를 확인합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 검수 환경, 검수 기간·방법 안내 |
| 고객이 준비할 것 | 기간 내 피드백, 재현 절차·스크린샷 등 |
| Newon | 이슈 분류(결함 / 범위 내 수정 / 범위 외) |

---

## 10. 수정

**목적:** 합의된 한도 안에서 이슈·피드백을 반영합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 수정본, 변경 요약 |
| 고객이 준비할 것 | 우선순위 있는 수정 요청, 범위 외는 별도 승인 |
| Newon | [06-change-request-policy.md](./06-change-request-policy.md) 적용 |

---

## 11. 최종 납품

**목적:** 산출물 전달과 인수 기록을 남깁니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 최종 산출물, 운영·인수 안내, 인수 확인서 |
| 고객이 준비할 것 | 인수 확인, 잔금 등 합의 조건, 운영 주체 확정 |
| Newon | [08-acceptance-form.md](./08-acceptance-form.md) · 유지보수 범위 재확인 |

---

## 커뮤니케이션 권장

- 피드백은 **한 채널·한 담당자**로 모아 주시면 일정 준수에 도움이 됩니다.  
- 구두 합의는 가능하면 **짧은 서면 요약**으로 남깁니다.  
- 긴급 장애와 일반 수정 요청은 구분해 주세요.
