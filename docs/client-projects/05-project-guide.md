# 프로젝트 진행 안내서

> 고객과 Newon이 **같은 순서·역할**을 공유하기 위한 안내입니다.  
> 프로젝트 유형(Studio만 / BUILD / 혼합)에 따라 일부 단계는 생략되거나 길이가 달라질 수 있습니다.  
> 프로젝트별 예외는 해당 **견적·SoW·계약**에 적힌 내용을 따릅니다.  
> 수정·변경의 **상세 기준**은 [06-change-request-policy.md](./06-change-request-policy.md)를 참고하세요.

---

## 한눈에 보기

```
상담
 → 요구사항 확정
 → 견적
 → 계약 · 계약금 확인 · 착수
 → 기획
 → 디자인
 → 개발 (해당 시)
 → 내부 QA
 → 고객 검수 (기본 5영업일)
 → 수정 (기본 2회)
 → 최종 작업 · 잔금 · 산출물 인계
 → 30일 Newon 구현 오류 대응
```

---

## 함께 알아두면 좋은 기본 규칙

| 주제 | 내용 |
|------|------|
| 착수 | **계약금 입금 확인** 후 작업 시작 |
| 수정 | 기본 **2회**. 1회 = 취합해 보내 주신 **피드백 묶음 1번**. Newon 구현 오류 수정은 횟수에 넣지 않습니다 |
| 검수 | 기본 **5영업일**. 가능하면 피드백을 모아 전달. **회신이 없다고 자동 승인되지 않습니다** |
| Change Request | 새 기능·페이지·큰 구조 변경 등은 비용·일정 확인 후 **승인하신 뒤** 진행합니다 |
| 인계 | **잔금 입금 확인** 후, 합의된 최종 산출물 전달 |
| 30일 대응 | 인수 확인일 **다음날부터 30일**, Newon **구현 오류**만 무상. 신규 요청·디자인 변경 등은 별도. **24시간 긴급 대응은 기본이 아닙니다** |
| Design Only | 디자인 계약에 **개발이 자동으로 포함되지 않습니다**. 개발이 필요하면 별도 견적·합의가 필요합니다 |
| 외부 비용 | 도메인·서버·API·SaaS 등은 보통 **고객 부담**입니다 (견적에 별도 명시) |

---

## 1. 상담

**목적:** 목표·대략 범위·서비스 축(Studio / Business)을 파악합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 상담 요약, 필요 시 질문지·다음 단계 안내 |
| 고객이 준비할 것 | 목적, 레퍼런스, 희망 일정·예산 감, 의사결정자 |
| Newon | 질문·범위 가설, Studio Design Only vs BUILD 구분 안내 |

---

## 2. 요구사항 확정

**목적:** 이후 견적·SoW의 기준을 만듭니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 정리된 요구사항(질문지 또는 동등 문서) |
| 고객이 준비할 것 | 질문지 회신·수정, 우선순위(Must/Should) 확정 |
| Newon | [01-requirements-questionnaire.md](./01-requirements-questionnaire.md) 기준 정리 |

---

## 3. 견적

**목적:** 범위에 대한 제안 금액·일정 골격을 제시합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 견적서 (**유효기간 기본 14일**, VAT 포함/별도 명시) |
| 고객이 준비할 것 | 검토·질의, 옵션 선택 여부 |
| Newon | [02-quote-template.md](./02-quote-template.md) 작성 · 사이트 시작가·별도 견적 체계 준수 |

요구범위가 바뀌면 유효기간 안이라도 재견적이 필요할 수 있습니다.

---

## 4. 계약 · 착수

**목적:** 범위·대가·일정을 합의하고 작업을 시작합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | SoW, 합의/계약, 킥오프 일정, 본 안내 |
| 고객이 준비할 것 | 승인, **계약금**, 자료·계정 제공 시작 |
| Newon | [03](./03-scope-of-work.md) 확정 · 내부 점검 후 킥오프 |

**착수 기준:** 범위 확정 + 합의/계약 + **계약금 입금 확인** (+ Critical 자료 수령).

결제 비율은 프로젝트 규모·기간에 따라 견적에 표시합니다 (소규모 50/50, 중·대형/장기 40/30/30 등).

---

## 5. 기획

**목적:** 정보 구조·플로우·화면·콘텐츠 구조를 합의합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | IA/플로우, 화면 목록, 기획 메모 또는 와이어 수준 산출물(합의 형식) |
| 고객이 준비할 것 | 피드백, 콘텐츠 초안·우선순위, 비즈니스 규칙 확인 |
| Newon | 범위 내 기획 · 범위 밖 요청은 Change Request로 분리 |

---

## 6. 디자인

**목적:** 합의된 시각·UI를 확정합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 디자인 시안·프로토타입(합의 툴), 수정본 |
| 고객이 준비할 것 | 브랜드 자산, **취합한 피드백** |
| Newon | SoW 디자인 범위 내 제작 · 기본 수정 2회 적용 |

**Design Only(Studio Digital)** 로 끝나는 경우: 이후 개발은 없거나, Business BUILD는 **별도 견적·계약**으로 이어갑니다.

---

## 7. 개발 (해당 시)

**목적:** 합의된 기능·플랫폼을 구현합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 진행 공유([11](./11-mid-project-update.md)), 스테이징/빌드 접근(합의 시) |
| 고객이 준비할 것 | API·계정·도메인, 약관 문구, 테스트 계정 정보, 중간 공유 피드백 |
| Newon | SoW 개발 범위 구현 · 환경변수·Secret은 안전하게 관리 · 중간 공유 11 |

가능하면 **고객이 서비스 계정을 소유**하고, Newon에는 필요한 **최소 권한**만 주시면 됩니다.

---

## 8. 내부 QA

**목적:** 고객 검수 전에 Critical 이슈를 줄입니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 검수 가능 안내, 체크 포인트 요약(선택) |
| 고객이 준비할 것 | 검수 일정 확보 |
| Newon | [07-delivery-checklist.md](./07-delivery-checklist.md) 기반으로 내부 점검 |

---

## 9. 고객 검수

**목적:** SoW 기준 합격 여부를 확인합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 검수 환경, **검수 기간(기본 5영업일)**·방법 안내 |
| 고객이 준비할 것 | 기간 내 **취합 피드백**, 재현 절차·스크린샷 등 |
| Newon | 이슈 분류(구현 오류 / 범위 내 수정 / Change Request) |

회신이 없더라도 **자동으로 승인된 것으로 처리하지 않습니다.**

---

## 10. 수정

**목적:** 합의된 한도 안에서 이슈·피드백을 반영합니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 수정본, 변경 요약 |
| 고객이 준비할 것 | 우선순위 있는 수정 요청(가능하면 한 번에 취합), 범위 외는 별도 승인 |
| Newon | [06-change-request-policy.md](./06-change-request-policy.md) 적용 |

---

## 11. 최종 납품 · 인계

**목적:** 잔금 확인 후 산출물을 전달하고 인수 기록을 남깁니다.

| | 내용 |
|--|------|
| 고객이 받는 것 | 최종 산출물, 운영·인수 안내, 인수 확인서 |
| 고객이 준비할 것 | 인수 확인, **잔금**, 운영 주체 확정 |
| Newon | [08-acceptance-form.md](./08-acceptance-form.md) · **30일 오류 대응 시작/종료일** 기록 · 잔금 확인 후 인계 |

---

## 12. 고객 지연 · 무응답

자료·피드백·승인·계정·권한이 늦어지면 **일정이 바뀔 수 있습니다.** (Newon 쪽 작업 지연과 구분합니다.)

| 경과 | 처리 |
|------|------|
| **5영업일** | 진행 확인 및 필요한 자료/피드백을 다시 안내합니다 |
| **10영업일** | 프로젝트를 **일시 보류**할 수 있으며, 기존 납품 예정일 유지를 **보장하지 않습니다** |
| **30일 이상** | 계약·진행률·완료 작업·발생 비용을 확인해 **종료 및 정산 절차를 검토**할 수 있습니다 |

- 무응답 = **자동 승인 아님**  
- 30일 = **자동 종료 아님**  
- 보류 후 다시 진행하실 때는 Newon의 **현재 일정**을 기준으로 재개일·납품일을 다시 맞춥니다.

## 커뮤니케이션 권장

- 피드백은 **한 채널·한 담당자**로 모아 주시면 일정 준수에 도움이 됩니다.  
- 구두 합의는 가능하면 **짧은 서면 요약**으로 남깁니다.  
- 긴급 장애와 일반 수정 요청은 구분해 주세요.  
- 포트폴리오 공개는 **동의가 확인되기 전 비공개**가 기본입니다. SoW·인수서에 선택해 주세요.
