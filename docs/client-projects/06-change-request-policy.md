---

## 1. 기본 수정의 정의

**기본 수정**이란, 이미 합의된 범위(SoW) 안에서  
산출물의 **오류 수정**, **합의된 디자인·카피의 소규모 조정**, **명확성·일관성 개선**을 말합니다.

다음에 해당하면 기본 수정으로 보기 어렵습니다.

- 새로운 화면·기능·플랫폼 추가  
- 확정된 정보구조·플로우의 재설계  
- 브랜드 방향·콘셉트의 전면 변경  
- 기술 스택·연동 대상의 교체  

---

## 2. 범위 내 수정 (In-Scope)

| 예시 | 처리 |
|------|------|
| SoW에 명시된 기능의 버그·오동작 | 우선 수정 |
| 합의된 시안 내 간격·정렬·오탈자·컬러 토큰 소조정 | 합의된 수정 한도 내 |
| 검수 기간 중 발견한 Critical / Major 결함 | 납품 전 해결 목표 |

**본 프로젝트 범위 내 수정 한도 (계약·SoW에서 확정 후 기입):**

| 항목 | 합의 내용 |
|------|-----------|
| 수정 라운드 또는 한도 | [프로젝트별 — 예: 「디자인 피드백 N라운드」 등. 미정 시 공란] |
| 검수 기간 | [ ] |
| 한도 초과 시 | 별도 협의 / Change Request |

## 3. 범위 밖 변경 (Out-of-Scope)

SoW **Out of Scope**이거나, In Scope로 해석하기 어려운 요청.

| 처리 | 내용 |
|------|------|
| 1 | 요청 접수·기록 |
| 2 | 영향(일정·비용·품질) 검토 |
| 3 | 고객 승인 후 진행 또는 다음 단계로 이관 |
| 4 | 승인 시 SoW 부록·견적 보완 |

승인 전 범위 밖 작업을 착수하지 않는 것을 원칙으로 합니다.

---

## 4. 신규 기능 추가

새로운 사용자 가치·화면·연동·권한·결제 흐름 등은 **신규 기능**으로 분류합니다.

- 별도 항목 견적 또는 Change Request  
- 일정 재계획  
- 필요 시 마일스톤 재정의  

---

## 5. 일정에 영향을 주는 변경

다음이 있으면 납품일이 달라질 수 있습니다.

- 범위 밖·신규 기능 승인  
- 고객 자료·피드백·승인 지연  
- 외부 계정·심사·서드파티 장애  
- 중대한 기술·보안 이슈 발견  

변경 시 Newon은 **조정된 일정안**을 공유합니다.

---

## 6. 추가 비용이 발생할 수 있는 경우 (유형)

금액을 미리 박지 않고, **발생할 수 있는 유형**만 안내합니다. 실제 금액은 건별 견적합니다.

- 범위 밖 변경·신규 기능  
- 합의된 수정 한도 초과  
- 추가 플랫폼·언어·환경  
- 유료 API·SMS·스토어·라이선스 등 외부 비용  
- 긴급 투입·야간·주말 작업(사전 합의 시에만)  
- 납품 후 운영·유지보수(별도 합의 없는 한 미포함)
